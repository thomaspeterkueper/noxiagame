## Gewünschte Änderung

Implement the smallest useful v0.1 foundation for NOXIA_TESTER_INTELLIGENT_01. First inspect the current NOXIA architecture and repository governance and adapt to existing game APIs rather than inventing parallel game state. Provide a read-only observation/state projection suitable for an autonomous player and a bounded typed gameplay action surface that uses the same authoritative game rules as human play wherever practical. Add persistent tester state sufficient for goals, recent observations/actions and memory across cycles. Implement a bounded Observe -> Goal/Plan -> Action -> Result loop that can run in a dedicated disposable test world. Add structured anomaly reporting for BUG and DEAD_END only in v0.1, including reproduction steps, expected/actual result, confidence and evidence. Reports must be suitable for later routing into the KUEPER ecosystem task bus, but the test player must not modify source code, canonical data, balance or game design itself. PROPOSAL, BALANCE and UX observations must not trigger autonomous implementation. Include deterministic deduplication/loop guards and a dry-run or deterministic test harness demonstrating at least one normal progression cycle and one anomaly-report cycle. Keep provider/LLM integration behind an adapter so agent identity does not depend on DeepSeek or any specific model. If the current game architecture lacks a safe authoritative action boundary, implement the minimal boundary first and document the remaining integration point rather than bypassing game invariants.
