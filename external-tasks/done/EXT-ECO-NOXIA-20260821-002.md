## Anlass

NOXIA should be able to act as an evidence-producing sensor for the KUEPER Ecosystem. Runtime gameplay and autonomous testers need a bounded way to turn reproducible game anomalies into cross-project requests without allowing game events to directly mutate repositories.

## Gewünschte Änderung

Implement the smallest NOXIA-side producer for the Game Observation -> Evidence -> TaskCandidate protocol defined by kueper-ecosystem/docs/architecture/GAME_OBSERVATION_TASK_PROTOCOL.md. Add a local observation sink usable by deterministic game assertions and NOXIA_TESTER_INTELLIGENT_01, stable fingerprints, occurrence aggregation, persistent deduplication and candidate gating. In v0.1 promote only reproducible BUG and DEAD_END observations automatically. Convert approved candidates into valid KUEPER outbox routing envelopes, but do not write directly to GitHub or Supabase from gameplay code. Preserve world_id, agent_id, reproduction, expected/actual, confidence, evidence provenance, cost_policy and estimated_effort. Add deterministic tests proving duplicate observations collapse to one candidate/request and a low-confidence/non-reproducible observation does not emit an implementation request.

## Erwartetes Ergebnis

NOXIA can locally record gameplay observations and emit a bounded, deduplicated KUEPER outbox request for a reproducible BUG or DEAD_END, while ordinary game actions, proposals, balance opinions and weak observations do not directly create development tasks. An unresolved finding must never be re-emitted merely because time elapsed; only an explicit RESOLVED state followed by recurrence may generate a REGRESSION request.

## Umsetzung (aktualisiert 2026-08-24)

Abgeschlossen als NOXIA Game-Observation-Producer v0.1 (`lib/game/observation/`):

- `types.ts` — Protokoll-Typen, Finding-Lifecycle, Kosten-/Prioritäts-Mapping und Outbox-Vertrag inklusive `estimated_effort`.
- `fingerprint.ts` — stabile Fingerprints (2× FNV-1a-32, deterministisch, ES2017).
- `sink.ts` — lokaler Observation-Sink mit Vorkommens-Aggregation, persistentem Lifecycle `UNEMITTED -> OPEN -> RESOLVED -> REGRESSION/OPEN`, Welt-Obergrenze und Snapshot/Restore.
- `producer.ts` — TaskCandidate → KUEPER-Outbox-Envelope; `cost_policy`, `estimated_effort`, `finding_event` und Provenienz bleiben an der Router-Grenze erhalten.
- `observationProducer.test.ts` — deterministische Regressionstests: ein ungelöstes Finding emittiert selbst nach 30 Tagen nicht erneut; erst `RESOLVED -> Wiederauftreten` emittiert `REGRESSION`; Lifecycle überlebt Snapshot/Restore; niedrige Konfidenz sowie PROPOSAL/UX erzeugen keine Tasks; Welt-Cap greift.
- Kein GitHub-/Supabase-Schreiben aus Gameplay-Code; normale Spielaktionen erzeugen keine Implementierungsaufgaben.
- Doku: `docs/observation-producer.md`; `tsconfig.json`: `allowImportingTsExtensions`.

Verifikation erfolgt durch den PR-/CI-Pfad mit den deterministischen Tests, Typecheck und Lint. Die beiden Review-Findings zu Finding-Lifecycle und verlorenem `estimated_effort` sind im Branch explizit adressiert.
